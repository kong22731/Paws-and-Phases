CSS ตกแต่งเฉพาะส่วนที่เป็น HTML (เลย์เอาต์ แผงแชท ถุงมือ แผงกล้อง หน้าสอนเล่น) ส่วนในเกมวาดด้วย Phaser

ตัวแปรสีและพื้นฐาน

  • :root ประกาศตัวแปร CSS (ขึ้นต้นด้วย --) เช่น --olive, --gap: 16px, --chat-w: 330px ใช้ซ้ำด้วย var(--ชื่อ) ตัวแปรชื่อ olive ถูกเปลี่ยนค่าเป็นสีฟ้าตามดีไซน์ใหม่ แต่คงชื่อเดิมไว้ ไม่ต้องแก้ส่วนอื่น
  • * { box-sizing: border-box; } ให้ความกว้างที่กำหนดรวมขอบและระยะในแล้ว คำนวณขนาดง่ายขึ้น
  • body จัดเนื้อหาไว้กลางจอด้วย flex และ overflow: hidden ไม่มีแถบเลื่อน

เลย์เอาต์แนวนอน

ตัวแปร --game-h คำนวณความสูงของเกม = ค่าที่ น้อยกว่า ระหว่าง (1) ความสูงจอ − ระยะขอบ และ (2) ความกว้างที่เหลือหลังหักแชท ÷ 1.6 (สัดส่วน 16:10) เกมจึงใหญ่ที่สุดเท่าที่จะใส่ได้โดยไม่ล้นทั้งแนวตั้งและแนวนอน

  • #app สูงตาม --game-h กว้างตามสัดส่วน aspect-ratio: 960 / 600 มุมมน มีเงา
  • #game-container ขยายเต็ม #app (inset: 0)
  • .name-input ช่องพิมพ์ชื่อสัตว์ ขอบมะกอก มุมมน ตัวอักษรกลาง

แผงแชท

  • #chat-screen กว้างคงที่ 330 สูงเท่าเกม จัดเรียงแนวตั้ง (flex column) ตอนมีคลาส disabled ช่องพิมพ์และปุ่มจางและกดไม่ได้ (pointer-events: none)
  • .cs-head แถวหัว: รูปวงกลม 56 พิกเซล อีโมจิอารมณ์มุมขวาล่าง (position: absolute) ชื่อยาวเกินตัดเป็น "..." (text-overflow: ellipsis) รูปที่ยังไม่มี src ถูกซ่อน
  • #cs-log ส่วนข้อความ flex: 1 = ยืดกินพื้นที่ที่เหลือทั้งหมด min-height: 0 + overflow-y: auto ให้เลื่อนได้ภายใน
  • .msg.pet ฟองซ้ายสีฟ้า มุมล่างซ้ายแหลม (เหมือนหางฟอง), .msg.user ฟองขวาสีขาว, .msg.system ป้ายเล็กกลางแผง, .meta บรรทัด intent ตัวเล็ก
  • .cs-tray ถาดประโยค/อีโมจิ ตัดขึ้นบรรทัดใหม่อัตโนมัติ (flex-wrap) ปุ่มรูปแคปซูล
  • #cs-mic ปุ่มกลม: ปกติแสดงไอคอนไมค์ มีคลาส has-text แสดงไอคอนส่ง มีคลาส listening เป็นสีแดงและเต้น (@keyframes pulse ขยาย 8% ที่ครึ่งทาง)
  • .flash แอนิเมชันกรอบเรืองแสงชั่วครู่ (ตอนกดปุ่มแชทในเกม)

ถุงมือ (#hand-glove)

  • position: fixed ที่มุม (0,0) แล้วย้ายด้วย transform จาก JavaScript z-index: 10000 อยู่บนสุด pointer-events: none = เมาส์ทะลุผ่าน (ไม่บังสิ่งที่อยู่ข้างใต้ ทำให้ elementFromPoint เจอปุ่มจริง) will-change: transform บอกเบราว์เซอร์ให้เตรียมเลื่อนบ่อย ลื่นขึ้น
  • ลูกด้านใน: เลื่อนด้วยตัวแปร --hot-x/--hot-y ให้ "กลางฝ่ามือ" ตรงกับจุดจริง ย่อด้วย --glove-scale และมีเงา
  • สลับรูป: ปกติแสดงรูปแบมือ คลาส fist หรือ pressed แสดงรูปกำมือ ตอนกดย่อลง 10%
  • .dragging เพิ่มแสงเรืองสีเหลือง, .dwelling แสดงวงแหวนชี้ค้าง (พื้นวงขาวโปร่ง + เส้นฟ้าที่ค่อยๆ เต็ม)
  • .hand-ripple วงคลื่นเหลืองตอนกด ขยายจาก 30% ถึง 140% พร้อมจางหาย (forwards = ค้างที่สถานะสุดท้าย)
  • button.hand-hover ปุ่ม HTML ที่ถุงมือชี้อยู่: มืดลงเล็กน้อยและมีกรอบเหลือง

แผงกล้อง (#cam-panel) และหน้าสอนเล่น

  • จุดสถานะเปลี่ยนสีตาม data-status: tracking เขียว (มีวงเรือง), nohand เหลือง, loading ฟ้ากระพริบ, error แดง
  • .cam-box กล่องภาพสัดส่วน 16:9 วิดีโอและ canvas ซ้อนกันเต็มกล่อง วิดีโอกลับด้าน scaleX(-1) ให้เหมือนส่องกระจก
  • .cam-gestures span ไอคอนท่ามือจางไว้ ตัวที่มีคลาส on สว่าง มีกรอบฟ้า ขยายเล็กน้อย
  • .collapsed ซ่อนภาพกล้องและหมายเหตุ (แถบสถานะและไอคอนยังแสดง)
  • #hand-tutorial ทับจอเกมทั้งหมด พื้นมืดโปร่ง การ์ดกลางจอสีมะกอก หัวข้อมีขอบตัวอักษร (-webkit-text-stroke + paint-order: stroke fill วาดขอบก่อนสีพื้น ขอบจึงไม่กินตัวอักษร) แถบความคืบหน้า และจุดบอกขั้น

สคริปต์ PowerShell ที่ ไม่ได้ทำงานตอนเล่นเกม ใช้เตรียมภาพล่วงหน้าเมื่อเพิ่มหรือเปลี่ยนรูป: แปลงภาพต้นฉบับขนาดใหญ่พื้นขาวให้เป็นภาพเล็กพื้นใส เกมโหลดเร็วขึ้นมาก ส่วนประมวลผลภาพเขียนด้วยภาษา C# ฝังในสคริปต์ (Add-Type) เพราะต้องวนทุกพิกเซลซึ่ง PowerShell ทำได้ช้า

ส่วนเริ่มต้น

  1. พารามิเตอร์: ขนาดภาพตัวเต็มสูงสุด 360, รูปหัว 220 และสวิตช์ -Review (สร้างภาพตรวจสอบที่ระบายสีส่วนที่ถูกลบ)
  2. $ErrorActionPreference = 'Stop' เจอข้อผิดพลาดให้หยุดทันที
  3. ลบโฟลเดอร์ผลลัพธ์เก่าก่อน (Windows ไม่เปลี่ยนตัวพิมพ์เล็ก-ใหญ่ของชื่อไฟล์เวลาเขียนทับ ซึ่งจะทำให้มีปัญหาบนเว็บ) แล้วสร้างใหม่
  4. อ่านไฟล์แก้ไขด้วยมือ sprite-fixes.txt (ถ้ามี): ตัดคอมเมนต์ (#) แยกคำ แล้วแปลงเป็นคำสั่งต่อภาพ เช่น remove x y (บังคับลบช่องตรงจุดนั้น), keep x y (บังคับเก็บ), pockets n, strict, keepshadow

SpriteTool.Process: ลบพื้นหลังภาพตัวละคร

  1. คัดลอกภาพเป็นแบบ 32 บิตมีช่องโปร่งใส แล้ว LockBits + Marshal.Copy ดึงพิกเซลทั้งหมดมาเป็นอาร์เรย์ไบต์ (เร็วกว่าอ่านทีละพิกเซลมาก) แต่ละพิกเซลมี 4 ไบต์เรียง B, G, R, A
  2. ขอบเป็นสีขาวไหม: สุ่มตรวจพิกเซลรอบขอบทุก 6 พิกเซล ถ้าขาวเกิน 85% = พื้นขาว (ลบได้) ไม่งั้นเป็นภาพฉาก
  3. Flood fill จากขอบ: เริ่มจากพิกเซลขอบทุกจุดที่ "ดูเป็นพื้นหลัง" (IsBg: สว่าง ≥ 175 และสีไม่จัด หรือ IsBgStrict ถ้าตั้ง strict) แล้วลามไปยังเพื่อนบ้านซ้าย ขวา บน ล่าง ที่เป็นพื้นหลังเหมือนกัน ใช้คิว (q, head, tail) แทนการเรียกซ้ำ กันหน่วยความจำล้น ผลคือพื้นขาวที่ต่อกับขอบทั้งหมด แต่สีขาวในตัวละครที่ถูกเส้นล้อมไว้ไม่ถูกแตะ
  4. ลบเงาใต้เท้า (ยกเว้น keepshadow): ใน 25% ล่างของภาพ ลามต่อจากพื้นหลังไปยังสีโทนอุ่น/เทาอ่อน เพราะเกมวาดเงาเองแล้ว
  5. ช่องสีขาวที่ถูกล้อม (เช่นช่องระหว่างขา) flood fill จากขอบเข้าไม่ถึง: หาทุกกลุ่มพิกเซลขาวล้วน (IsPocketWhite) ให้หมายเลขกลุ่ม ถ้าตรงกับจุดใน sprite-fixes ใช้คำสั่งนั้น ไม่งั้นตัดสินอัตโนมัติ: ตรวจวงรอบนอกห่าง 5 พิกเซล นับสัดส่วนเส้นขอบเข้ม (dark) และสีอ่อนไล่เฉด (light) ช่องพื้นหลังจริงจะติดเส้นขอบทันที ส่วนสีขาวในภาพ (ฟอง เมฆ แสงสะท้อน) จะค่อยๆ ไล่เป็นสีอ่อน ลบเฉพาะช่องใหญ่ (≥ 0.2% ของภาพ) ที่ขอบเข้ม ≥ 35% และสีอ่อน ≤ 50% ช่องเล็กอย่างประกายในตาไม่ถูกลบ
  6. ตั้งพิกเซลพื้นหลังทั้งหมดให้โปร่งใส (alpha = 0)
  7. ทิ้งเศษจุด: แบ่งพิกเซลที่เหลือเป็นกลุ่มที่ติดกัน ทิ้งกลุ่มที่เล็กกว่า 0.15% ของกลุ่มใหญ่สุด
  8. ขอบนุ่ม: พิกเซลที่ติดพื้นที่โปร่งใส ยิ่งสว่างยิ่งโปร่ง (ไม่ต่ำกว่า 40) ขอบตัวละครจึงไม่เป็นเส้นขาวหยัก
  9. หากรอบ ที่มีตัวละคร (พิกเซลทึบ > 20) เพื่อตัดขอบว่าง
  10. ถ้าใช้ -Review บันทึกภาพตรวจสอบ: ช่องที่ลบเป็นสีฟ้า ช่องขาวที่เก็บไว้เป็นสีเขียว
  11. บันทึกภาพตัวเต็มที่ตัดขอบและย่อแล้ว
  12. รูปหัว: ภาพพื้นขาว ใช้สี่เหลี่ยมจัตุรัสด้านละ 66% ของด้านสั้น จากส่วนบนของตัว จุดกึ่งกลางแนวนอนคือค่าเฉลี่ยตำแหน่งของพิกเซลทึบในส่วนบน (หัวอาจไม่อยู่กลางภาพ) ภาพฉากใช้กลางภาพค่อนบน (40%)
  13. คืน "cutout" หรือ "scene"

SpriteTool.Resize: ย่อภาพทั่วไป

ใช้กับไอเทม แบนเนอร์ ภาพ UI และหน้าปก ถ้า removeBg และมุมภาพทึบ: flood fill จากขอบด้วยสีที่ใกล้สีมุมภาพ (ผลต่างรวม ≤ 60) ลบพื้นสีเดียว (ขาวหรือดำ) แล้วตัดขอบว่าง ย่อให้อยู่ในกรอบที่กำหนดโดยไม่ขยาย บันทึกเป็น PNG หรือ JPEG คุณภาพ 85 (แบนเนอร์ ไม่ต้องโปร่งใส ไฟล์เล็กกว่า)
